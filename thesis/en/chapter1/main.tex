\section{Background and Motivation}
\label{sec:intro_overview}

Every day, commercial businesses and public institutions handle large numbers of documents, such as retail receipts, invoices, tax forms, and medical records. In traditional workflows, clerks had to read these papers and manually enter important fields, like dates, vendor names, and monetary amounts, into software systems. This manual process takes considerable time and often results in human error. While early optical character recognition (OCR) systems could turn scanned images into text, they produced unorganized strings of words without identifying which numbers represented prices or which text blocks represented customer names.

To address this challenge, Key Information Extraction (KIE) has become a primary focus in document intelligence \cite{cui2021documentai}. In visually rich documents, semantic meaning depends not only on the words themselves, but also on where they appear on the page and how they look visually \cite{xu2020layoutlm,huang2022layoutlmv3}. For instance, whether a word like "Total" refers to a general header or a final payment amount depends on its position relative to the table rows below it. Therefore, a successful model needs to process text, geometric coordinates, and image pixels at the same time.

Recent vision-language models, particularly LayoutLMv3 \cite{huang2022layoutlmv3}, combine textual tokens, bounding box coordinates, and visual image patches inside a unified Transformer. This design achieves strong results on standard benchmarks. However, when adapting LayoutLMv3 to real-world form and receipt datasets, several practical issues arise:
\begin{enumerate}
    \item \textbf{Textual and visual competition:} Because document images are split into many visual patches, visual tokens can take up a large part of the attention weight. This can sometimes dilute attention on fine-grained textual details \cite{xie2026roap}.
    \item \textbf{Lack of explicit structural groupings:} LayoutLMv3 represents position using raw 2D bounding boxes $(x_0, y_0, x_1, y_1)$. It does not explicitly tell the model which words share the same line, column, or paragraph block, forcing the self-attention mechanism to infer these relationships from scratch.
    \item \textbf{Inconsistent entity predictions within segments:} In documents like forms, an entity such as a long sentence or address often spans several words. Because tokens are classified independently, the model can predict conflicting labels in the middle of a single text line.
    \item \textbf{Boundary ambiguity between neighboring fields:} When a label and its value appear side by side on the same horizontal line, such as "Date: 12/10/1998", the model frequently merges them into one continuous entity.
\end{enumerate}

These practical challenges motivate the research presented in this graduation thesis.

\section{Problem Formulation}
\label{sec:problem_statement}

In standard document key information extraction, a document page is given as an image $\mathbf{I} \in \mathbb{R}^{H \times W \times 3}$. An OCR engine first parses the image to produce a sequence of $L$ subword tokens along with their geometric bounding boxes.

We represent each document sample as a collection of tokens and the page image:
\begin{equation}
    \mathcal{D} = \left\{ (w_i, \mathbf{b}_i, s_i) \right\}_{i=1}^{L} \cup \{\mathbf{I}\},
    \label{eq:doc_representation}
\end{equation}
where:
\begin{itemize}
    \item $w_i \in \mathcal{V}$ is the $i$-th subword token in the document vocabulary $\mathcal{V}$.
    \item $\mathbf{b}_i = (x_0^{(i)}, y_0^{(i)}, x_1^{(i)}, y_1^{(i)}) \in [0, 1000]^4$ represents the normalized bounding box coordinates for token $w_i$, scaled to a standard $1000 \times 1000$ coordinate grid:
    \begin{equation}
        x_{0,1}^{(i)} = \left\lfloor \frac{\tilde{x}_{0,1}^{(i)}}{W} \times 1000 \right\rfloor, \quad
        y_{0,1}^{(i)} = \left\lfloor \frac{\tilde{y}_{0,1}^{(i)}}{H} \times 1000 \right\rfloor.
    \end{equation}
    \item $s_i \in \{0, 1, \dots, S-1\}$ denotes the line segment index indicating which visual text line token $w_i$ belongs to.
\end{itemize}

We formulate KIE as a token-level sequence labeling task using the standard IOB2 tagging format. Given $K$ target entity types $\mathcal{E} = \{e_1, e_2, \dots, e_K\}$, the label set $\mathcal{Y}$ has size $2K + 1$:
\begin{equation}
    \mathcal{Y} = \{\texttt{O}\} \cup \bigcup_{k=1}^{K} \left\{ \texttt{B-}e_k, \, \texttt{I-}e_k \right\},
\end{equation}
where \texttt{B-}$e_k$ indicates the first token of an entity of class $e_k$, \texttt{I-}$e_k$ represents following tokens inside the same entity, and \texttt{O} designates background words.

The goal is to train a model $f_{\Theta}(\mathcal{D})$ that predicts a label sequence $\hat{\mathbf{Y}} = (\hat{y}_1, \dots, \hat{y}_L) \in \mathcal{Y}^L$ to maximize the exact entity-level F1 score over the target test set.

\section{Limitations in Existing Models}
\label{sec:challenges}

While pretrained multimodal Transformers have improved document parsing substantially, standard fine-tuning strategies still encounter specific architectural bottlenecks:

\begin{enumerate}
    \item \textbf{Equal Treatment of Spatial Axes:}
    In baseline LayoutLMv3, all bounding box dimensions $(x_0, y_0, x_1, y_1, w, h)$ are mapped to identical embedding dimensions and concatenated directly. However, in printed documents, horizontal and vertical coordinates serve different purposes. Horizontal coordinates determine word order and column placement, whereas vertical coordinates dictate line progression and section hierarchy. Treating both axes identically limits the model's ability to distinguish line breaks from column gaps.

    \item \textbf{Absence of Segment Context Exchange:}
    Even when words in the same line share coordinates, self-attention processes every token individually. There is no explicit representation for the text segment as a whole. As a result, longer entities often suffer from prediction drift, where tokens inside the same sentence receive incompatible tags.

    \item \textbf{Lack of Explicit Boundary Supervision:}
    The standard training objective optimizes cross-entropy on each token independently. It does not penalize abrupt label switches between consecutive words that clearly belong to the same visual line, leading to false entity boundaries.

    \item \textbf{Misalignment Between Image Patches and Text:}
    While LayoutLMv3 uses pretraining objectives like Word-Patch Alignment, fine-tuning on downstream datasets typically relies only on classification loss. Without continuing alignment supervision, the correspondence between visual patches and text features can degrade during fine-tuning \cite{wang2023aetnet}.
\end{enumerate}

\section{Proposed Contributions}
\label{sec:contributions}

To address these limitations while keeping the model lightweight, this thesis develops and tests several structural enhancements for LayoutLMv3:

\begin{enumerate}
    \item \textbf{Hierarchical Position Encoding (HPE):}
    We cluster word boxes into reading lines, columns, and logical blocks using spatial heuristics. These hierarchical indices are converted into learnable embeddings and projected into the token embedding layer, providing explicit layout structure before self-attention.

    \item \textbf{Segment Context Module (SCM):}
    We aggregate token representations in each text segment via mean pooling to form line-level vectors. A lightweight Transformer encoder models relationships between these segments, and a ReZero gate blends the contextualized segment representation back into the tokens alongside a segment-start indicator embedding.

    \item \textbf{Intra-Line Boundary Loss:}
    We construct an auxiliary loss that examines consecutive token pairs on the same line. The model learns to distinguish between pairs within the same entity and pairs that mark an entity transition, sharpening entity boundaries.

    \item \textbf{Cross-Modal Contrastive Loss:}
    We introduce an alignment objective during fine-tuning that pulls corresponding text tokens and visual patches closer in embedding space, improving visual-textual consistency on noisy scans.

    \item \textbf{Systematic Multi-Seed Evaluation:}
    We evaluate our methods across three random seeds on the FUNSD and CORD benchmarks using an NVIDIA A100 GPU. The proposed architecture improves entity F1 score on FUNSD from $89.92 \pm 0.85\%$ to $91.58 \pm 0.16\%$, while reducing variance across training runs.
\end{enumerate}
